## Périmètre et état

Accueil, page Chine et première étape du formulaire examinés sur le site public. Validation à vide testée sans envoi. Code source analysé au commit 6e20a8c916a6cb6edc8dbf9907c948a40eb4ca84. Pas de test de paiement ni d'envoi en production. Rendu mobile et délivrabilité des emails non vérifiés. Les constats UX sont des hypothèses à mesurer, pas des gains de conversion garantis.

L'identité actuelle (ivoire, vert profond, typographie, photos personnelles) mérite d'être conservée. La page Chine fournit déjà le tarif, les inclus/exclus, un programme progressif et un sommaire. « Faire ma demande » décrit correctement le parcours actuel, qui n'est pas une réservation immédiate.

## Environnement de test

Branche de travail : `staging/ux-audit`. La branche `main` n'est pas modifiée et aucun workflow de production n'est lancé.

Construction : `npm ci`, puis `node scripts/build-staging.mjs`. Le dossier `dist-staging` est une copie statique isolée, sans API serveur et sans secrets. Les formulaires conservent leur validation et simulent une réponse positive en mémoire ; aucune inscription n'est créée. Le bandeau de test indique explicitement les simulations. Les actions HTML des formulaires sont neutralisées et la politique CSP bloque réseau applicatif, formulaires natifs et iframes. Les liens externes Instagram/email/téléphone restent des liens réels ; ne pas les utiliser pour un test d'envoi.

Le mode test possède des directives noindex et robots.txt. Ces directives ne constituent pas un contrôle d'accès : utiliser un hébergement privé pour la revue.

L'ancien script d'aperçu neutralisait uniquement les actions `/api/` ou `#apercu`. Il ne neutralisait pas les actions Formspree actuelles. Utiliser le nouveau script pour les essais.

La copie de test initiale conserve le design actuel : les modifications UX ci-dessus restent à réaliser et comparer. Une publication future sur le site réel doit faire l'objet d'une demande explicite ; ne jamais fusionner le bandeau ou les simulations dans la production.
